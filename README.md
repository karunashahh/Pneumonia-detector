# Pneumonia Detection from Chest X-Rays

## Live Demo

[Try the Pneumonia Detector](https://pneumonia-detector-karuna.streamlit.app/)

Binary classification of chest X-rays (NORMAL vs PNEUMONIA) using transfer learning,
with an explicit focus on the precision/recall trade-off relevant to medical screening,
and on catching and fixing a real data-leakage issue rather than reporting an inflated
accuracy number.

## Problem

Screen chest X-rays for signs of pneumonia. Framed as a **screening** task, not a
diagnostic one — the cost of a missed real case is treated as worse than a false alarm,
which shapes the threshold and metric choices below.

## Dataset

- Kaggle `chest_xray` dataset (5,856 images total: NORMAL / PNEUMONIA)
- **Found and fixed a real issue:** the official train/val/test folders have patient-level
  leakage — the same patient's X-rays appear in more than one split. Verified this
  (~40% of test patients also appeared in training) and rebuilt the split by patient ID
  instead of by file, with an explicit check that confirms zero overlap.

## Approach

- MobileNetV2 backbone (switched from an initial VGG16 attempt for training speed on CPU),
  transfer learning with a small classifier head
- Class weighting to handle the NORMAL:PNEUMONIA imbalance
- Two-phase training: frozen backbone → fine-tuned last two blocks at a low learning rate
- Data augmentation (rotation, zoom, flip, brightness)
- Threshold tuned via a full precision/recall/F1/F2 sweep (not left at the default 0.5)

## Results

| Metric | Leaky split (official folders) | Clean split (patient-level, this model) |
|---|---|---|
| Test accuracy | 76% | **89.2% ± 0.1%** (3 seeds, full 10-epoch training) |
| ROC-AUC | 0.832 | **0.950 ± 0.002** (3 seeds) |
| PNEUMONIA recall | 92% | see notebook Section 11 |
| NORMAL recall | 49% | see notebook Section 11 |

**Notable finding:** the clean, leakage-free split scored *higher* than the leaky one,
not lower — the opposite of the naive expectation that leakage would inflate results.
This is reported as-is rather than forced into the "leakage inflated our numbers"
narrative: it's a more honest and more interesting result. A likely explanation is that
grouping by patient changed which images ended up in the test set, producing a set that
happens to be somewhat easier to classify — worth investigating further, not fully
explained here.

Stability was checked at two epoch counts: a quick 3-epoch check showed high variance
(±7.6 points accuracy) simply because training hadn't converged yet; the full 10-epoch
setup (5 epochs frozen + 5 fine-tuned, matching the actual training pipeline) converges
reliably to the same result regardless of seed.

- **Baseline comparison:** a simple CNN trained from scratch on the same data, to quantify
  the actual benefit of transfer learning rather than assuming it.
- **Calibration:** checked whether confidence scores are trustworthy, not just whether
  predictions are correct.
- **Stability:** accuracy/AUC reported as mean ± std across multiple random seeds, at the
  full training length actually used for the final model.

## Explainability (Grad-CAM)

- Correct predictions (both classes) show the model attending to broad lung fields.
- Some false positives showed attention on non-lung regions instead. Tested whether this
  correlated with image contrast/quality — did not find a statistically significant
  difference, reported as an open question rather than a forced conclusion.

## Limitations

- Grad-CAM resolution is limited by MobileNetV2's small final feature map (coarse,
  blocky heatmaps at this input size).
- Public dataset, single source of imaging equipment/protocol — real-world generalization
  beyond this dataset is untested.
- This is a screening aid, not a diagnostic tool, and is not validated for clinical use.

## Project structure

```
pneumonia-detectioncode.ipynb   # full training + evaluation + analysis pipeline
app.py                     # Streamlit demo app
requirements.txt           # dependencies
MODEL_CARD.md              # model card (intended use, performance, caveats)
pneumonia_mobilenetv2_clean_split.keras   # trained model (generated by the notebook)
```

## How to run

**Notebook** (training + full analysis):
```bash
pip install -r requirements.txt
jupyter notebook pneumonia-detectioncode.ipynb
```
Set `DATA_ROOT` in the config cell to your local copy of the `chest_xray` dataset.

**Streamlit app** (after the notebook has produced the `.keras` model file):
```bash
streamlit run app.py
```
Then open the printed local URL in your browser.
